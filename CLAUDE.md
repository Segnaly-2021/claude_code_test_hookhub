## Commands

Run from this directory (`hookhub/`); npm is the package manager (`package-lock.json`).

- `npm run dev` — dev server at http://localhost:3000
- `npm run build` — production build (also the type-check gate; there is no separate `tsc` script — use `npx tsc --noEmit` for types only)
- `npm run start` — serve the production build
- `npm run lint` — ESLint over the whole project; `npx eslint app/page.tsx` for a single file

No test runner is configured.

## Stack

Next.js 16.4 (App Router) + React 19.3 + TypeScript (strict) + Tailwind CSS v4. The app is currently the unmodified `create-next-app` scaffold: a single route in `app/page.tsx` under the root layout `app/layout.tsx`.

## Things that differ from older Next.js / Tailwind setups

As AGENTS.md says, do not rely on memory for Next.js APIs. The version-matched docs are shipped in `node_modules/next/dist/docs/` (`01-app/01-getting-started`, `01-app/02-guides`, `01-app/03-api-reference`); read the relevant page before writing code.

- **`cacheComponents: true`** in `next.config.ts` — the Cache Components model is on, which changes how data fetching, caching, and static/dynamic rendering work. See `01-app/01-getting-started/08-caching.md` and `02-guides/migrating-to-cache-components.md` before adding data fetching or route segment config.
- **`partialPrefetching: true`** — see `02-guides/adopting-partial-prefetching.md` before working on links/navigation or loading states.
- **`experimental.agentFeedback: true`** — see `02-guides/ai-agents.md`.
- **Tailwind is wired through Turbopack, not PostCSS.** There is no `postcss.config.*` or `tailwind.config.*`; `next.config.ts` registers `@tailwindcss/turbopack` as a loader for `*.css`. Theme tokens are defined in CSS via `@theme inline` in `app/globals.css` (`background`, `foreground`, and the Geist `--font-sans` / `--font-mono` variables set in `app/layout.tsx`). Add design tokens there.
- **Global route types**: layouts/pages use the generated `LayoutProps<"/route">` / `PageProps` helpers (see `app/layout.tsx`) rather than hand-written prop types. These come from `next-env.d.ts` and `.next/types`, which are generated by `next dev` / `next build` and are gitignored — run one of them if the types are missing.
- ESLint uses flat config (`eslint.config.mjs`) with `eslint-config-next` core-web-vitals + typescript presets.

## Conventions

- Path alias `@/*` maps to the project root (e.g. `@/app/...`).
- Dark mode follows `prefers-color-scheme` via CSS variables in `globals.css` plus Tailwind `dark:` variants; there is no theme toggle.
